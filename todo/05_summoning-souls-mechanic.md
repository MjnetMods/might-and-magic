# Souls as a Summoning Resource

Summoning should be soul-based: souls need to exist in-game as an actual concept/resource (item, entity drop, fluid — TBD) that Summoning recipes consume, rather than the current contracts/offerings/entity-trade model in `design/30_summoning-path.md` having no soul mechanic at all.

**Why:** "summoning is souls" is the intended fantasy for the school, but nothing in the current Summoning design produces or spends a soul resource today.

**Q:** `design/40_sanguine-path.md` already owns "Soul Remnants" as one of its three pillars (funerary rites, vampiric transformation). Does Summoning share that same soul concept, or does it need its own distinct soul mechanic (e.g. Sanguine = remnants of the dead, Summoning = souls bound from summoned/traded entities)? Needs a design pass across both docs before this is promotable — resolve the overlap before picking an implementation.
